# PostgreSQL fresh-provisioning compatibility

AutoSQL supports the same managed PostgreSQL provisioning lifecycle on
PostgreSQL 14, 15, 16, 17, and 18. The version matrix proves adoption of an
existing schema, provisioning its managed projection into an empty target,
apply and semantic reinspection, a converged no-op, and an unrelated
incremental change.

Cluster-level target creation and external-target verification are documented
in [PostgreSQL database target bootstrap](postgresql-database-bootstrap.md).

## Supported managed projection

| Capability | Adopt and inspect | Create from empty | Incremental changes |
| --- | --- | --- | --- |
| Managed database target or externally supplied database | Yes | Managed target: yes; external target: verify only | Mutable settings, reviewed rename, explicit drop; immutable locale/encoding changes require replacement |
| Schemas, enums, domains, and sequences | Yes | Yes | Per negotiated driver operations |
| Allowlisted extensions with exact package/version/schema/trust policy | Yes | Yes when the package is installed and authority is bound | Update, relocatable schema move, comments, and guarded drop |
| Ordered composite types, including nested, array, collated, and extension-backed attributes | Yes | Yes | Rename, owner/comment, add/drop/rename attributes, reviewed type changes, and guarded drop |
| Permanent, non-partitioned tables and columns | Yes | Yes | Yes |
| Parameterized column types, arrays, enum/domain types, and native `cidr`/`inet`/`macaddr` network types | Yes | Yes | Safe type changes only |
| Bounded PostgreSQL defaults, including schema-bound enum/domain casts, arrays, `now()`, UUID generation, and exact `nextval` references | Yes | Yes without relying on `search_path` | Yes |
| `GENERATED ALWAYS` and `GENERATED BY DEFAULT` identity columns | Yes | Yes | Identity-mode alteration is fail-closed |
| Stored generated columns with exact column and routine dependencies | Yes | Yes | Creation only; generated-expression alteration is fail-closed |
| Primary, unique, check, and foreign-key constraints | Yes | Yes | Rename, online validation, explicit rebuild, and drop |
| Standalone table and materialized-view indexes, including expressions, predicates, `INCLUDE`, opclasses, storage parameters, and tablespaces | Yes | Yes, including built-in `inet_ops` for btree/hash/GiST/SP-GiST `inet` and `cidr` columns | Rename, drop, explicit rebuild, and concurrent online phases |
| Reviewed SQL and PL/pgSQL functions and procedures | Yes | Yes with an exact reviewed digest | Compatible replace, owner/comment, rename, and drop |
| Table and view triggers, including constraint triggers and transition tables | Yes | Yes when their routine is reviewed; unqualified inspected targets are bound to the exact containing schema | Rebuild, rename, enable-mode changes, and drop |
| Row-level security policies and table ENABLE/FORCE state | Yes | Yes | Deny-first create, transactional replace, rename, and drop |
| Roles and schema-object ownership | Yes without password hashes | Yes | Guarded alter/rename, ownership transfer, and reassign-before-drop |
| Role memberships | Yes | Yes | ADMIN guard, cycle rejection, revoke, rename topology, and PG16+ INHERIT/SET options |
| Object and column grants | Yes | Yes | Exact privilege edges, grant-option changes, partial/full revoke |
| Default privileges for future objects | Yes | Yes | Exact owner/schema/class edges, grant-option changes, revoke |
| Comments on all managed resources above | Yes | Yes | Add, replace, and remove |
| Provable views and materialized views | Yes | Yes, including complex queries whose parsed relation set exactly matches the captured graph | Within the parser-bounded query and canonical projection graph |

The stored-generated expression grammar is structural and fail-closed. It
accepts literals, column references, bounded casts and arrays, and exact
immutable SQL function calls declared by dependency edges. It does not pass
arbitrary PostgreSQL expressions through to execution. Calls with same-name
overloads currently fail closed because AutoSQL does not guess PostgreSQL's
argument-type resolution from a declared edge.

Routine bodies are executable only when their exact-source `sha256:` digest is
present in the `reviewed_routine_digests` render option. Catalog text and
authored HCL are inert without that separate authority. AutoSQL preserves the
reviewed source's line structure and dollar-quote tag through rendering, so
line comments in SQL and PL/pgSQL retain their PostgreSQL semantics. Line
endings are normalized to LF before hashing. SQL and PL/pgSQL are the default
language allowlist; unsafe languages, privileged bodies,
transaction-controlling procedures, and `SECURITY DEFINER` routines have
additional fail-closed policy gates.

Constraint and index expressions are parsed structurally. Application routine
calls require one exact dependency and immutable volatility. Undeclared or
ambiguous overloads, subqueries, version-unsafe JSON nodes, unavailable access
methods/operator classes, and invalid concurrent-index remnants are reported
before a plan is published.

Complex view and materialized-view queries are parsed as exactly one PostgreSQL
query statement. AutoSQL walks the full query AST, including nested subqueries,
and requires its resolved table/view/materialized-view set to equal the captured
`references` graph. Missing, extra, ambiguous, duplicate, self, and
catalog-qualified relation edges fail before SQL is emitted. Captured projection
columns must remain contiguous, uniquely named, typed, and canonical.
Projection columns using managed enum, domain, or composite types retain an
exact `uses` dependency on that type. Missing, duplicate, unrelated, or
wrong-kind projection dependencies fail before SQL is emitted.

The built-in network operator class is method- and type-bound: `inet_ops` is
accepted only unqualified or as `pg_catalog.inet_ops`, only for direct `inet`
or `cidr` columns, and only with PostgreSQL's btree, hash, GiST, or SP-GiST
access methods. PostgreSQL does not provide a GIN `inet_ops`; GIN and custom
same-name operator classes remain fail-closed.

## Privileged and external boundary

Server package installation remains external: AutoSQL inventories
`pg_available_extension_versions` and advertised update paths but never installs
operating-system packages. Database-level `CREATE EXTENSION`, update, relocatable
schema move, comments, and guarded drop are managed only after an explicit
allowlist and exact version/schema/trust policy pass. Extension-owned catalog
members are attributed to the owning extension and are never replayed
independently; application-referenced members remain inert prerequisites.
`postgres.PreflightProvisioning` reports unsupported metadata, missing review
authority, unavailable packages, or policy failures before apply.

`postgres.PreflightBootstrapProvisioning` adds the non-secret authority pass.
It deterministically binds database creation, roles, extensions, schema
objects, grants, and the final ownership handoff to named principals before
any SQL is rendered. The shared CLI/operator contract supports current-session,
external-secret, AWS IRSA, and OIDC authentication. Only provider references
are persistent; resolved passwords, tokens, and connection URLs cannot enter
documents, plans, logs, status, or fingerprints.

An “empty target” can now include the full
extension/type/table/column/key/index/routine/trigger graph. Extension and
database-security authority remains explicit; AutoSQL does not silently install
server packages or execute unreviewed source.

## Executable evidence

- `TestCompleteCellProvisioningParity` exercises the complete lifecycle and
  review boundary in `pkg/postgres/plan_integration_test.go`.
- `TestConstraintIndexInventoryScaleParity` provisions and explicitly recounts
  315 indexes, 69 primary keys, 56 foreign keys, 45 checks, and 27 unique
  constraints.
- `TestRoutineTriggerInventoryScaleParity` provisions both the 15-routine cell
  inventory and the 32-routine repository inventory together with all six
  trigger patterns, then proves HCL and semantic no-op convergence.
- `TestRLSPolicyInventoryBootstrapParity` provisions 14 policies across seven
  FORCE RLS tables, then proves HCL, create/reinspect/no-op, predicate
  replacement, rename, and drop convergence. It executes as the runtime role
  to prove same-tenant access, cross-tenant invisibility, and WITH CHECK denial.
- `TestRoleLifecycleAndWriteOnlyPassword` proves passwordless role bootstrap,
  exact owner handoff, configuration/rename/retirement, and a runtime-only
  password update whose value never enters a document, plan, or fingerprint.
- `TestMembershipLifecycleVersionParity` covers grant, guarded option changes,
  role rename, revoke, HCL round-trip, and PostgreSQL-version-aware semantics.
- `TestGrantInventoryLifecycleParity` reproduces the three cell GRANT edges and
  proves grant-option, partial revoke, full revoke, HCL, and no-op convergence.
- `TestDefaultPrivilegeFutureObjectParity` proves that later-created tables
  receive exactly the desired defaults and stop receiving them after revoke.
- `TestExtensionCreateUpdateSchemaMoveAndGuardedDrop` and
  `TestExtensionOwnedMembersDoNotProduceDuplicateLifecycle` prove exact-policy
  install, update, relocation, teardown, and member attribution.
- `TestCompositeInspectHCLRoundTripPreservesOrderTypesAndCollation` and
  `TestCompositeCreateAttributeLifecycleRenameAndGuardedDrop` prove rich type
  modeling, HCL parity, safe attribute maintenance, rename, and teardown.
- `TestConstraintIndexBootstrapParity`,
  `TestConcurrentIndexCreateRebuildDropLifecycle`,
  `TestFunctionReplaceRenameDropLifecycle`, and
  `TestTriggerFamilyBootstrapParity` cover representative maintenance and
  online phases.
- `.github/workflows/zdm-postgres-matrix.yml` runs that test on PostgreSQL
  14–18.
- `examples/hcl-postgres/generated.hcl` demonstrates both identity modes,
  comments, advanced defaults, and a stored generated column with exact
  dependencies.

## Release-note wording

Use this scope when announcing the capability:

> Fresh PostgreSQL provisioning on PostgreSQL 14–18 now includes relational
> constraints, standalone indexes, review-authorized functions/procedures, and
> triggers, RLS policies, extensions, composite types, roles, memberships,
> grants, and default privileges in addition to the existing schema, type,
> table, column, default, identity, generated-column, view, and comment
> lifecycle. One credential-free whole-database plan creates or verifies the
> target, resumes transactional and online phases from digest-bound
> checkpoints, and supports later maintenance plans. The count-bearing
> matrix provisions 315 indexes, 69 primary keys, 56 foreign keys, 45 checks,
> and 27 unique constraints. Extension packages, reviewed routine digests, and
> server/database/security credentials remain explicit external authority.
